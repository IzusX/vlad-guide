# VladGuide — отчёт о продукте

## 1. Резюме

**VladGuide** — цифровой сервис для самостоятельного знакомства с Владивостоком и Приморьем.

Продукт решает проблему туриста без гида: вместо поиска информации по десятку источников пользователь получает готовые маршруты с картой и персональным ИИ-гидом по каждой достопримечательности.

**Статус:** MVP реализован. 4 маршрута, 16 достопримечательностей, интерактивная карта, чат с ИИ-гидом по месту.
**Аудитория:** самостоятельные туристы 18-35 лет, семьи из центральной России, гости из Китая.
**Рынок:** Приморский край — один из ключевых туристических регионов ДВ. Турпоток 4,07 млн поездок в 2025 году (+4,5% к 2024), из них ~1,5 млн — из других регионов России, ~434 тыс. — из-за границы. Регион третий в России по популярности среди иностранных гостей.
**Бизнес-модель:** Freemium (B2C) + доступ для отелей и хостелов (B2B2C). Основной доход — оплата за полный доступ, оптовые продажи размещениям, промо-интеграции локального бизнеса.
**Команда:** 10 человек, ПИКД — дизайн, фронтенд, контент.

Цель продукта — стать точкой входа для гостя города: открыл — выбрал время — пошёл гулять с гидом в кармане.

## 2. Проблема и решение

**Проблема туриста во Владивостоке:**

*   Информация разбросана: 2ГИС показывает здания, TripAdvisor — отзывы 5-летней давности, блоги — противоречивые советы. Единой curated подборки под разное время (1 час / 2 часа / полдня) нет.
*   Живой гид дорого (от 3000₽ за экскурсию) и требует бронирования. Для спонтанной прогулки в центре это неудобно.
*   Языковой барьер: значительная часть гостей — из Китая, им нужен доступный формат на русском/английском без поиска переводчика.
*   Запрос на автономность: современный турист 18-35 лет хочет идти в своём темпе, а не в группе.

**Наблюдение:** турист в центре Владивостока тратит 30-40 минут только на то, чтобы понять куда идти и что перед ним за здание. Ценность теряется.

**Решение — VladGuide:**

| Боль | Как решает продукт |
| :--- | :--- |
| Не знаю куда идти, мало времени | Готовые маршруты по длительности и теме: "Исторический центр за 1 час", "Виды и море за 2 часа" и т.д. |
| Что это за здание? Хочу историю, а не сухие факты | Карточка каждого места + кнопка "Спросить гида" — ИИ отвечает на месте с контекстом именно этой точки |
| Хочу гулять сам, без группы | Полностью самостоятельный сценарий: карта, линия маршрута, точки, чат — всё в телефоне |
| Нужен язык/детали/легенды | Гид отвечает на уточняющие вопросы, держит историю диалога в рамках одного места (до 5 пар вопрос-ответ) |

Продукт не конкурирует с маркетплейсом гидов, а занимает нишу "цифровой гид для самостоятельной прогулки".

## 3. Продукт

**Концепция:** подборка маршрутов + интеллектуальный помощник по достопримечательностям. Вместо каталога исполнителей — готовый контент и ответы на месте.

**Что входит в MVP:**

*   **4 маршрута:** Исторический центр (1ч), Исторический центр (2ч), Виды и море (2ч), Полдня: центр + море. Покрывают 90% запросов гостя на 1-2 дня.
*   **16 достопримечательностей:** центральные точки города с описанием, координатами, фото-заглушкой и короткой справкой.
*   **Интерактивная карта:** OSM + Leaflet, линия маршрута, маркеры с попапами, автоподстройка границ. Работает без ключей и платежей.
*   **ИИ-гид по месту:** чат, привязанный к конкретной точке. Помнит контекст диалога, отвечает в пределах 8000 символов, обрабатывает ошибки провайдера (нет ключа / лимит) без падения интерфейса.
*   **Адаптивность и тема:** корректно на 360px, светлая/тёмная/системная тема.

**Сценарий использования:**

1. Турист открывает главную — видит 4 карточки маршрутов с длительностью и количеством точек.
2. Выбирает "Исторический центр за 1 час" — попадает на карту с линией и списком мест.
3. Нажимает "Спросить гида" у Спортивной набережной — чат открывается с контекстом этого места, можно задать вопрос: "Почему это место так называется?"
4. На мобильном — автопрокрутка к чату, на десктопе — чат закреплён рядом с картой.

**Отличие от аналогов:**

*   **2ГИС / Яндекс Карты:** показывают где, но не рассказывают зачем идти и что смотреть по порядку.
*   **TripAdvisor / Суточно:** отзывы и бронирование, нет локальной кураторской подборки и живого диалога.
*   **Живые гиды / Аудиогиды:** дорого или статично (запись нельзя спросить). VladGuide — интерактивно и доступно в любой момент.
*   **Ключевое отличие VladGuide:** связка `маршрут -> точка -> диалог с контекстом точки`. Гид знает где находится пользователь.

**Техническая база:** Next.js + Leaflet + OSM + JSON-контент + Vercel. Позволяет держать нулевую стоимость инфраструктуры и быстро обновлять контент без бэкенда.

## 4. Целевая аудитория

### Сегмент А — Самостоятельные туристы 18-35 лет (основной)

Портрет: приезжает на 2-4 дня, путешествует без тура, планирует через телефон. Хочет увидеть город без переплат за гида. Готов платить за удобство, но не готов платить 3000-5000₽ за экскурсию.

Сценарий: прилетел, заселился, вечером ищет "что посмотреть во Владивостоке за 2 часа". Открывает VladGuide, выбирает маршрут под время, идёт с телефоном.

Доля в продукте: ~50% пользователей.

### Сегмент B — Семьи и гости из центральной части России

Портрет: 30-45 лет, с детьми, приезжает в отпуск на 5-7 дней. Нужен простой сценарий без сложной логистики. Ценит готовый план с понятной длительностью.

Сценарий: выбирает "Полдня: центр + море" на выходной, проходит с детьми, задаёт гиду простые вопросы.

Доля: ~30%.

### Сегмент C — Иностранные гости (Китай, Корея)

Портрет: групповой или индивидуальный туризм, языковой барьер. Ищет информацию на понятном языке, часто через рекомендации отеля.

Сценарий: получает QR в отеле, открывает маршрут, использует гида для перевода и контекста по местам.

Доля: ~20%, но с наибольшим потенциалом для B2B2C (отели сами раздают доступ).

### Общее поведение

Все сегменты объединяет запрос на автономность и экономию времени. Пользователь хочет не список достопримечательностей, а готовый сценарий прогулки с возможностью спросить.

## 5. Рынок

Оценка дана по открытым данным о туристическом потоке в Приморском крае. Цифры используются как ориентир для бизнес-модели, а не как результат собственного исследования.

**Базовые данные по региону:**

*   Турпоток Приморья — **4,07 млн поездок в 2025 году** (+4,5% к 2024 году, 3,9 млн). Источник: краевое министерство туризма Приморского края.
*   Из них ~**1,5 млн** поездок — туристы из других регионов России.
*   ~**434 тыс.** — иностранные гости. Приморье — третий регион России по популярности среди иностранцев.

| Уровень | Объём | Комментарий |
| :--- | :--- | :--- |
| **TAM** | ~4,1 млн поездок в год | Весь турпоток Приморья. Все, кто теоретически может заинтересоваться прогулкой по Владивостоку. |
| **SAM** | ~700 тыс. человек | Самостоятельные туристы во Владивостоке, которые ищут информацию онлайн и гуляют без гида. Оценка ~17% от TAM на основе доли самостоятельных поездок и доли столицы края в потоке. |
| **SOM** | ~35-70 тыс. пользователей в год | Реалистичная доля на старте при партнёрствах с 30-50 размещениями и органике. 5-10% от SAM. |

**Динамика:** турпоток на Дальний Восток растёт, Владивосток — точка притяжения из-за близости к Азии, гастрономии и морской тематики. Сезонность выражена: пик май-сентябрь (около 70% трафика), спад в зимние месяцы.

**Вывод:** рынок нишевый, но достаточный для freemium-продукта с B2B-распределением. Не требует федеральных масштабов для окупаемости — достаточно закрепиться в центре города.

**Позиционирование VladGuide:**

*   Не маркетплейс гидов, а замена ему в сценарии "хочу сам".

*   Низкий порог входа: без регистрации и бронирования, открыл — пошёл.
*   Нулевая стоимость инфраструктуры (OSM/Leaflet) vs зависимость конкурентов от платных API.

## 7. Бизнес-модель

Модель комбинированная: B2C freemium для прямого трафика + B2B2C для дистрибуции через размещения и локальный бизнес.

### 7.1. Потоки дохода

| Поток | Механика | Цена для клиента |
| :--- | :--- | :--- |
| **B2C — разовый доступ** | 1 маршрут бесплатно ("Исторический центр за 1 час"), остальные открываются оплатой. Доступ на 48 часов — хватает на 1-2 дня прогулок. | 199₽ за 1 маршрут / 299₽ за все 4 |
| **B2C — подписка (опционально)** | Для тех кто остаётся на неделю. Не основной поток на старте. | 399₽ / 7 дней |
| **B2B2C — отели и хостелы** | Размещение покупает пакет QR-доступов и выдаёт гостю при заселении (листовка/наклейка на ресепшн). Гость сканирует — получает полный доступ без оплаты. | Пакет 100 активаций — 5000₽ (50₽/шт). Подписка для отеля 3000₽/мес безлимит для гостей |
| **Промо-интеграции** | Кафе, музеи, сувенирные — платят за отметку "Рекомендуем по пути" внутри маршрута. Только релевантные точки, без баннеров. | от 4000₽/мес за точку |

Основной фокус на старте — B2C + B2B2C-пакеты. Промо — после набора аудитории от 3000 пользователей в месяц.

### 7.2. Почему freemium работает здесь

Бесплатный маршрут снимает барьер: турист пробует продукт без регистрации и карты. Конверсия в оплату строится на том, что первый маршрут уже дал ценность (карта, история, гид), второй — хочется пройти завтра. Для отеля пакет дешевле, чем печатать свои буклеты, и даёт добавленную ценность заселению.

### 7.3. Путь денег

Пользователь -> оплата (ЮKassa/СБП) -> доступ открывается по ссылке/QR -> часть выручки покрывает AI-API и остаётся маржой. B2B — счёт для юрлица, акты.

## 9. Экономика

Расчёт на допущениях, формулы вынесены для проверки. Валют — рубли.

### 9.1. Переменные затраты на пользователя

*   **AI-API:** средняя сессия — 2-3 вопроса гиду. Себестоимость 1 ответа при лимите 600 токенов — 2-4₽ на моделях уровня gpt-4o-mini / open-source через провайдера. Закладываем 8₽ на платящего пользователя (берущего 2 сессии) и ~2₽ на бесплатного (если задаёт 1 вопрос).
*   **Платежка:** 3-4% от платежа (ЮKassa/СБП).
*   **Инфраструктура:** 0₽ (Vercel Free, OSM без ключа, JSON-контент). Домен ~100₽/мес при годовом делении.

### 9.2. Unit-экономика B2C

| Показатель | Значение | Комментарий |
| :--- | :--- | :--- |
| **CAC за визит** | 0-50₽ | 0₽ для B2B2C/органики, до 50₽ при таргете в ВК. Базовое допущение — 10₽ |
| **CAC на платящего** | ~250₽ | 10₽ за визит ÷ 4% конверсии |
| **ARPU платящего** | 260₽ | Средний чек: смесь 199₽ и 299₽, берём 260₽ |
| **Конверсия free -> pay** | 3-5% | Бенчмарк для freemium в туризме без агрессивного маркетинга |
| **Валовая маржа на платящего** | ~242₽ | 260₽ - 8₽ AI - 4% платежка (~10₽) |
| **Доход на 100 бесплатных визитов** | 780-1300₽ | 100 × 3-5% × 260₽ |
| **Валовая прибыль на 100 визитов до CAC** | ~490-1120₽ | за вычетом AI (~150-240₽) и платежки (~30-50₽) |

**Вывод:** платящий пользователь окупает привлечение с первой покупки — маржа 242₽ против CAC ~250₽, то есть безубыточность достигается уже на втором платеже. Важная оговорка: при CAC 10₽ за визит каждая сотня бесплатных визитов даёт валовую прибыль ~490-1120₽ до вычета стоимости привлечения (1000₽). Поэтому масштабирование имеет смысл только при органическом трафике и B2B-канале, где CAC близок к нулю. Это ограничение зафиксировано в разделе 13 как ограничение модели роста.

### 9.3. Unit-экономика B2B2C

Пакет 100 активаций за 5000₽. Отель раздаёт ~60 из 100 (остальные сгорают).

*   Выручка: 5000₽ с одного партнёра
*   Себестоимость AI: 60 × 8₽ = 480₽
*   Маржа с партнёра: ~4520₽
*   20 активных партнёров: ~90 400₽ маржи в месяц при низкой загрузке

### 9.4. Сценарий на месяц (проверочный)

Берём консервативный трафик: 2500 визитов (1500 органика/B2B2C + 1000 из отелей).

*   B2C: 1500 × 4% × 260₽ = 15 600₽
*   B2B: 10 пакетов × 5000₽ = 50 000₽
*   Промо: 1 точка — 4000₽
*   **Выручка: ~69 600₽**
*   **Переменные затраты:** AI — 60 платящих × 8₽ (480₽) + 600 B2B-активаций × 8₽ (4800₽) + ~1840 бесплатных × 2₽ (3680₽) + платежка 4% от B2C-части (624₽) ≈ **9600₽**
*   **Валовая прибыль: ~60 000₽**

Фиксированных затрат на старте нет (команда — студенты, разработка — своя). Даже при половине трафика продукт остаётся в плюсе за счёт нулевой инфраструктуры.

**Точка безубыточности:** постоянные затраты на старте — домен (~100₽/мес) и тестовый рекламный бюджет (допустим 30 000₽/мес). При марже 242₽ с платящего это ~125 платящих доступов в месяц, или 7 B2B-пакетов (маржа 4520₽ × 7). Ниже этой отметки продукт финансово отрицателен.

| **MVP** | Сейчас | 4 маршрута, 16 точек, карта OSM, ИИ-гид по месту, тёмная тема, деплой | Линт 0 ошибок, e2e 22/22, demo без регистрации |

Расширение языка на китайский — после проверки спроса через отели, не в MVP.

## 12. Риски

| Риск | Вероятность | Что делаем |
| :--- | :--- | :--- |
| **Зависимость от AI-провайдера** (рост цены, лимиты, блокировка) | Средняя | Поддержка 3 форматов API (openai-chat / openai-responses / anthropic-messages), таймаут и лимит 8к символов, смена модели без переписывания кода. При росте цены — переход на более дешёвую модель с ростом маржи. |
| **Сезонность туризма** (70% трафика май-сентябрь) | Высокая | B2B-пакеты сглаживают просадку (отели продают доступ круглый год гостям в командировках), контент про зимние сценарии (каток, видовые). |
| **Копирование конкурентами** (2ГИС/Яндекс добавят подборки) | Низкая на старте | Скорость и локальность: curated маршруты + диалог по точке сложно скопировать без контента. Барьер — партнёрская сеть в центре, а не технология. |

Некритичные риски (сбои оплаты, ошибки контента) закрываются обработкой ошибок в интерфейсе — чат не падает при `CONFIG_MISSING / RATE_LIMIT`, оплата не блокирует просмотр бесплатного маршрута.

## 13. Слабые стороны проекта

Раздел фиксирует ограничения проекта осознанно: часть из них принята как осознанный компромисс, часть требует работы. Для каждого ограничения указано, влияет ли оно на прибыльность, на пользу для пользователя и на восприятие продукта.

### 13.1. Ограничения продукта

| Ограничение | Причина | Осознанно ли | Влияние на прибыль | Влияние на пользователя | Влияние на имидж |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Малая глубина контента:** 4 маршрута и 16 точек на старте | Объём работы ограничен сроком; каждая точка требует проверки фактов и координат | Да | Ограничивает ценность подписки — пользователь выбирает из малого числа вариантов | Среднее: один маршрут изучает полностью, для второго города уже нужна новая подборка | Низкое: на демо 4 маршрута выглядят полноценно |
| **Нет фото и аудио у точек** | Требует лицензирования и обработки изображений, не входит в MVP | Да | Косвенное: снижает время сессии и частоту возвратов | Заметное: визуальный контент — главный ожидаемый формат у туриста | Среднее: без фотографий карточка выглядит менее нарядно |
| **Ответы ИИ без проверки фактов** | Каждая точка не верифицировалась вручную целиком; гарантируется только общий контекст и лимиты | Да | Риск: неточный ответ снижает доверие и отток | Заметное: история места — это и есть ценность продукта | Низкое: невидимо для пользователя |
| **История диалога не сохраняется между сессиями** | Осознанное решение: не собирать данные о пользователе без необходимости | Да | Отрицательное: нельзя вернуть пользователя персонализированным предложением | Заметное: после перезагрузки контекст потерян | Положительное: «не следим за пользователем» — сильный аргумент для B2B и отелей |
| **Нет офлайн-режима** | Карта и тайлы требуют сети; офлайн-версия требует кэша и существенно больше места | Да | Ограничивает сценарий в метро и в горах | Заметное: в маршруте с плохим сигналом карта не грузится | Низкое |
| **Один город** | Фокус на старте — проверка модели на конкретной географии | Да | Ограничивает масштаб: выход в другие города требует нового контента и партнёров | Нейтральное: турист во Владивостоке не страдает | Нейтральное |

### 13.2. Ограничения бизнес-модели

| Ограничение | Причина | Осознанно ли | Влияние на прибыль | Влияние на пользователя | Влияние на имидж |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **Платёжеспособный спрос не подтверждён** | Гипотеза: турист не привык платить за цифровой гид при платформах-конкурентах с нулевой ценой | Нет — гипотеза | Критичное: без подтверждения модель не работает | Прямое: при отказе от оплаты продукт должен оставаться полезным | Нейтральное: честная формулировка «проверяем гипотезу» лучше необоснованных обещаний |
| **B2B-канал не подтверждён договорённостями** | Отели не заинтересованы на старте; QR-доступ — способ дистрибуции, а не состоявшаяся сделка | Да, как гипотеза | Критичное: B2B даёт 70%+ выручки в модели | Положительное: бесплатный доступ для гостей отеля | Нейтральное |
| **Маржинальность упирается в AI-себестоимость** | Стоимость ответа зависит от выбранной модели и провайдера | Да | Среднее: при росте числа вопросов маржа сжимается | Прямое: при перерасходе придётся ограничивать ответы | Нейтральное |
| **Сезонность не сглажена полностью** | B2B-пакеты покрывают лишь часть зимнего спада | Да | Среднее: зимние месяцы дают ~30% выручки от пика | Косвенное: зимний турист реже находит продукт в поиске | Нейтральное |
| **Нет отдела продаж и поддержки** | Команда из 10 человек, роли продуктовые | Да | Критичное: при росте партнёрств без продаж канал встанет | Косвенное: медленная реакция на обращения | Среднее: для партнёра важна скорость ответа |
| **Зависимость от одного AI-провайдера по умолчанию** | Технически поддерживается три формата, но провайдер не выбран окончательно | Нет — нужно закрыть до запуска платежей | Критичное: смена провайдера ломает маржинальность | Косвенное: при сбое провайдера чат недоступен | Нейтральное |

### 13.3. Что делаем с каждой группой ограничений

**Не влияют на прибыль и пользователя — закрывать не нужно:**
Фото в MVP, офлайн-режим, один город, глубина контента на старте. Эти ограничения осознанные и не препятствуют проверке основной гипотезы. Расширение производится после подтверждения спроса.

**Требуют работы до запуска платежей:**
Выбор AI-провайдера с зафиксированной ценой ответа, регистрация для приёма платежей, оферта и политика конфиденциальности, тестовое соглашение с 2-3 отелями для проверки B2B-гипотезы. Это приоритетные задачи ближайшего этапа.

**Требуют проверки гипотезы, а не разработки:**
Платёжеспособность спроса, готовность отелей к партнёрству, реальная конверсия free -> pay. До подтверждения этих трёх параметров продукт следует позиционировать как эксперимент, а не как готовый бизнес. Это принципиально важно для честности перед партнёрами и инвесторами: неподтверждённые цифры в разделе 9 — расчётные допущения, а не результаты замеров.

**Влияют на имидж, но не на деньги:**
Отсутствие фотоконтента и медленная поддержка партнёров. Решаются в процессе: фотобанк местами — отдельная задача контент-роли, SLA для партнёров — после первых договорённостей.

## 14. Юридическая модель

Раздел описывает как продукт может работать легально без регистрации юрлица на старте и что потребуется при масштабировании.

### 14.1. Форма на старте

На этапе MVP юрлицо не требуется. Права на код и контент принадлежат команде по устной договорённости, репозиторий публичный (`IzusX/vlad-guide`). Для приёма платежей достаточно одного участника как самозанятого (НПД) или ИП.

*   **Самозанятый:** подходит для B2C до 2,4 млн ₽/год, чек через "Мой налог", налог 4% (физлица) / 6% (юрлица при B2B). Ограничение — нельзя перепродавать чужой товар, но продажа доступа к своему сервису — услуга, подходит.
*   **ИП на УСН 6% "Доходы":** если выручка выше лимита самозанятого или нужны расчёты с юрлицами по безналу с актами. На старте достаточно ИП без сотрудников.

Рекомендация для отчёта: "Старт — самозанятый, при выручке >150 тыс ₽/мес — переход на ИП УСН 6%". Двойного налогообложения нет.

| Компонент | Лицензия / условия | Что обязаны соблюдать |

| **Leaflet** | BSD-2 | Свободно, без атрибуции кода. Бренд Leaflet указывать не обязаны (в тесте проверяется отсутствие флага). |

### 14.3. Персональные данные (152-ФЗ)

*   **Что храним:** в MVP на сервере ничего не храним — чат держит историю в памяти браузера (до 5 пар на место), платежи идут через эквайринг, регистрации нет.
*   **Что нужно сделать при запуске платежей:** разместить Политику конфиденциальности и Согласие на обработку (шаблон 1 страница), указать оператора (ИП/самозанятый), цель — "предоставление доступа к сервису". Хостинг на Vercel — данные обрабатываются за пределами РФ, но при отсутствии хранения ПДн это допустимо для MVP с уведомлением.
*   **Cookies/аналитика:** если подключим Яндекс Метрику — нужен баннер согласия. На старте без метрики — не требуется.

### 14.4. Договоры с клиентами

*   **B2C:** публичная оферта на сайте (1-2 страницы): предмет — предоставление доступа к цифровому контенту на 48 часов / 7 дней, цена, порядок возврата по ЗоЗПП (цифровой товар — возврат до начала использования). Чек через "Мой налог" или эквайринг.
*   **B2B:** договор с отелем/хостелом на поставку кодов доступа, счёт, акт. Формулировка — "информационные услуги". НДС нет при УСН/НПД.

### 14.5. Налоги (упрощённо)

При выручке из раздела 9: 70 тыс ₽/мес = 840 тыс ₽/год — укладывается в лимит самозанятого. Налог ~4-6% от выручки, без взносов. При масштабировании (выше 2,4 млн) — ИП УСН 6% + взносы.

Отдельных разрешений, лицензий на гид-деятельность не требуется — продукт является информационным сервисом, не туроператором.
