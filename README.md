# VladGuide AI

Веб-сервис для самостоятельных прогулок по Владивостоку: тематические маршруты, рассказы о достопримечательностях, интерактивная карта и ИИ-гид по выбранному месту.

## Возможности

- Каталог маршрутов с длительностью, описанием и тематическими тегами.
- Карточки мест с адресами, историей и ссылками на 2ГИС.
- Карта с маркерами и последовательностью точек прогулки.
- Чат с уточняющими вопросами, отдельной историей для каждого места, повтором запроса и очисткой диалога.
- Светлая, тёмная и системная темы; выбор темы сохраняется в браузере.

Каталог содержит 4 маршрута и 16 мест. Без настроенного ИИ-провайдера чат блокируется и показывает уведомление о необходимости настройки. Каталог и карта остаются доступны независимо от чата.

## Технологии

| Слой | Инструменты |
| --- | --- |
| Приложение и серверные обработчики | Next.js 16, App Router |
| Интерфейс | React 19, TypeScript |
| Стили | Tailwind CSS 4, CSS-переменные палитры Yerba |
| Карта | Leaflet, React Leaflet, OpenStreetMap |
| Контент | JSON-файлы в репозитории |
| ИИ | Серверные HTTP-адаптеры для Chat Completions, Responses и Anthropic Messages |
| Проверки | Node.js test runner, Playwright, ESLint, TypeScript |

Отдельная база данных и отдельный backend не требуются. Страницы маршрутов формируются из локального каталога; интерактивные части работают в клиентских компонентах.

## Локальный запуск

Требования: Node.js 20.9 или новее и pnpm. Для запуска модульных тестов требуется Node.js 22.6+ с поддержкой type stripping; разработка и проверки выполнялись на Node.js 24. Версия pnpm указана в `package.json`.

```bash
git clone https://github.com/IzusX/vlad-guide.git
cd vlad-guide
pnpm install --frozen-lockfile
cp .env.example .env.local
# Заполните обязательные переменные для включения ИИ-чата.
pnpm dev
```

Приложение доступно по адресу [http://localhost:3000](http://localhost:3000). Без `.env.local` сайт запускается с отключённым чатом.

## Настройка ИИ-провайдера

Все обязательные переменные нужно заполнить в `.env.local` или окружении хостинга. После изменения локального файла перезапустите сервер.

| Переменная | Назначение |
| --- | --- |
| `AI_API_FORMAT` | `openai-chat`, `openai-responses` или `anthropic-messages` |
| `AI_API_URL` | Полный URL endpoint, включая путь метода |
| `AI_API_KEY` | Ключ API выбранного провайдера |
| `AI_MODEL` | Точный идентификатор модели у провайдера |
| `AI_TIMEOUT_MS` | Таймаут запроса и чтения ответа: 1 000–120 000 мс; по умолчанию 30 000 |
| `AI_MAX_OUTPUT_TOKENS` | Лимит генерации: 1–4 096 токенов; по умолчанию 600 |
| `AI_CHAT_TOKEN_PARAM` | Для `openai-chat`: `max_tokens` (по умолчанию) или `max_completion_tokens`, согласно API провайдера |

Первые четыре переменные обязательны. Модель по умолчанию не подставляется: у разных провайдеров различаются имена и доступность моделей. Пустые или некорректные настройки отключают чат. URL должен использовать HTTPS; HTTP разрешён только для loopback-адресов при локальном тестировании. URL с логином, паролем или фрагментом не допускается.

### Примеры endpoint

| Подключение | `AI_API_FORMAT` | `AI_API_URL` |
| --- | --- | --- |
| OpenRouter Chat Completions | `openai-chat` | `https://openrouter.ai/api/v1/chat/completions` |
| OpenAI Chat Completions | `openai-chat` | `https://api.openai.com/v1/chat/completions` |
| OpenAI Responses | `openai-responses` | `https://api.openai.com/v1/responses` |
| Anthropic Messages | `anthropic-messages` | `https://api.anthropic.com/v1/messages` |

Для OpenAI-совместимых протоколов используется `Authorization: Bearer`, для Anthropic — `x-api-key` и `anthropic-version: 2023-06-01`. Формат выбирается по API поставщика, а не по названию модели: например, Claude через OpenRouter использует формат OpenRouter.

Адаптеры поддерживают текстовые запросы без стриминга и инструментов. Специфические для модели параметры reasoning/temperature не передаются. Параметр лимита токенов для Chat Completions нужно выбрать по документации конкретного сервиса.

Переменные читаются только сервером. Не используйте для ключа префикс `NEXT_PUBLIC_`. Файлы `.env*` исключены из Git, кроме `.env.example` с пустым ключом. Статус чата не возвращает ключ, endpoint или сырые ошибки провайдера.

### Работа чата

```text
GET /api/chat → статус конфигурации → включение или блокировка формы

Место + вопрос + недавняя история → POST /api/chat
                                      ↓
                              Проверка запроса
                                      ↓
                         Контекст места из каталога
                                      ↓
                            Выбранный API-адаптер
                                      ↓
                         Ответ или безопасная ошибка
```

Наличие настроек не доказывает, что ключ действителен или квота доступна. `GET` не вызывает провайдера и не расходует токены. Реальная авторизация проверяется при отправке вопроса.

История хранится только в памяти открытой страницы, отдельно для каждого места. При переключении мест диалог и черновик сохраняются; после обновления страницы — очищаются. Сервер и провайдер получают максимум последние 5 завершённых пар «вопрос — ответ» плюс текущий вопрос. Неудачные сообщения не включаются в последующий контекст. Механизмы сохранения диалога у провайдера (`previous_response_id` и аналоги) не используются; для Responses передаётся `store: false`. Это не заменяет политику хранения данных самого провайдера.

Одновременно выполняется один запрос. Очистка текущего диалога отменяет ожидающий запрос со стороны клиента; уже начатая обработка у внешнего провайдера может продолжиться. Ответ всегда привязывается к исходному месту, даже при переключении карточки. Повтор запускается вручную и не дублирует вопрос.

Сервер добавляет собственную инструкцию и описание выбранного места. История принимает только роли `user`/`assistant`; клиентские системные инструкции и настройки поставщика не используются. Ответ зависит от модели и качества подготовленных данных — инструкция не является гарантией отсутствия фактических ошибок.

### Лимиты и ошибки

- Вопрос: до 2 000 символов, непустой текст.
- История: до 10 сообщений, в чередующихся завершённых парах `user`/`assistant`.
- Возвращаемый текст: до 8 000 символов.
- Входящий запрос: до 128 КиБ фактически прочитанных данных.
- Ответ провайдера: до 256 КиБ; используется только текст, без reasoning/tool-блоков.
- Таймаут включает получение и чтение ответа; автоматических повторов нет.

Неполная конфигурация блокирует чат. Ошибки авторизации, квот, модели, сети, таймаута, недоступности сервиса и неожиданного ответа показываются понятными сообщениями без стеков и сырых JSON провайдера. Временные ошибки позволяют повторить запрос. Отказ модели предлагает переформулировать вопрос.

Ограничение параллельности относится к одному открытому чату. Глобальный rate limiting, авторизация и защита публичного API от массового использования не реализованы; лимиты провайдера остаются отдельным ограничением. Фото, распознавание объектов и бронирование не реализованы.

## HTTP API

### `GET /api/chat`

Ответ содержит только безопасный статус конфигурации, без тестового обращения к модели:

```json
{
  "available": false,
  "code": "CONFIG_MISSING",
  "message": "ИИ-гид не подключён. Настройте провайдера, модель и API-ключ на сервере."
}
```

При полной конфигурации `available` равен `true`, `code` — `READY`. Неверные значения дают `CONFIG_INVALID`. Ответ не кэшируется.

### `POST /api/chat`

```json
{
  "placeId": "railway-station",
  "question": "А что интересного в архитектуре?",
  "history": [
    { "role": "user", "content": "Расскажи о вокзале" },
    { "role": "assistant", "content": "Предыдущий ответ гида" }
  ]
}
```

`history` можно не передавать для первого вопроса. Успех:

```json
{
  "answer": "Текст ответа",
  "source": "ai",
  "placeId": "railway-station"
}
```

Ошибка:

```json
{
  "error": {
    "code": "RATE_LIMIT",
    "message": "Достигнут лимит запросов или исчерпана квота ИИ-гида. Попробуйте позже.",
    "retryable": true
  }
}
```

| HTTP | Ситуация |
| --- | --- |
| 400 / 413 | Неверный запрос / превышен размер тела |
| 404 | Место не найдено |
| 422 | Отказ модели отвечать на вопрос |
| 429 | Лимит запросов или квота провайдера |
| 502 | Ошибка доступа, модели, сети или формата ответа провайдера |
| 503 | ИИ не настроен или временно недоступен |
| 504 | Таймаут |
| 499 | Отмена запроса |

## Редактирование каталога

### Места — `data/places.json`

Каждое место содержит `id`, `name`, `address`, краткое описание `short`, подробный рассказ `description`, координаты `lat`/`lng` и категории `category`. Поля рассказа используются для контекста ИИ.

### Маршруты — `data/routes.json`

Каждый маршрут содержит `id`, `title`, `summary`, длительность `duration` (`1h`, `2h` или `4h`), `placeIds` в порядке посещения и тематические `tags`. Все `placeIds` должны существовать в каталоге мест.

После изменения данных для production-развёртывания нужна новая сборка. Карта соединяет точки прямыми линиями: это порядок посещения, а не навигация по улицам. Координаты, доступность проходов, исторические сведения и оценку времени следует проверять при обновлении каталога.

## Проверки и production-запуск

```bash
pnpm test
pnpm lint
pnpm build
pnpm start
```

`test` проверяет конфигурацию, адаптеры, ошибки, лимиты и состояние диалогов без настоящих ключей и запросов к модели. `build` собирает приложение и проверяет TypeScript. `start` запускает готовую сборку.

После `pnpm build` команда `pnpm test:integration` проверяет настоящий `/api/chat` через локальный тестовый провайдер: три протокола, историю, валидацию, квоты и таймаут. Настоящие ключи не используются; тестовые процессы завершаются автоматически.

Браузерные тесты работают на настольной и мобильной ширине и подменяют HTTP-ответы чата:

```bash
pnpm exec playwright install chromium
pnpm test:e2e
```

Можно использовать установленный Google Chrome: `PLAYWRIGHT_CHANNEL=chrome pnpm test:e2e`. По умолчанию используется `http://127.0.0.1:3000`; адрес можно задать через `PLAYWRIGHT_BASE_URL`. В конфигурации тестов сервер разработки запускается при необходимости. Не оставляйте реальный ключ в окружении тестов.

## Развёртывание

Приложение можно разместить на Vercel или сервере с поддержкой Next.js и Node.js. Переменные `AI_*` задаются в окружении хостинга, а не в репозитории. Статический хостинг без серверных обработчиков не подходит для `/api/chat`. Таймаут выполнения функций хостинга должен быть больше настроенного таймаута ИИ.

Карта требует доступа к OpenStreetMap; стандартные изображения маркеров загружаются с unpkg. Шрифты Inter и Libre Baskerville загружаются при сборке через `next/font` и затем обслуживаются приложением. Лимиты и стоимость размещения и ИИ определяются выбранными поставщиками.
