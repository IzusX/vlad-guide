# VladGuide AI

Веб-сервис для самостоятельных прогулок по Владивостоку: тематические маршруты, рассказы о достопримечательностях, интерактивная карта и чат-гид по выбранному месту.

## Возможности

- Каталог маршрутов с длительностью, описанием и тематическими тегами.
- Карточки мест с адресами, историей и ссылками на 2ГИС.
- Карта с маркерами и последовательностью точек прогулки.
- Чат по выбранной достопримечательности.
- Светлая, тёмная и системная темы; выбор сохраняется в браузере.

Каталог содержит 4 маршрута и 16 мест. Без настроенного ИИ-провайдера сайт и карта работают самостоятельно, а чат возвращает справочную информацию с явным уведомлением о недоступности ИИ.

## Технологии

| Слой | Инструменты |
| --- | --- |
| Приложение и серверные обработчики | Next.js 16, App Router |
| Интерфейс | React 19, TypeScript |
| Стили | Tailwind CSS 4, CSS-переменные палитры Yerba |
| Карта | Leaflet, React Leaflet, OpenStreetMap |
| Контент | JSON-файлы в репозитории |
| Чат | Серверный HTTP-запрос к OpenAI-совместимому API |

Отдельная база данных и отдельный backend не требуются. Страницы маршрутов формируются из локального каталога; интерактивные части работают в клиентских компонентах.

## Локальный запуск

Требования: Node.js 20.9 или новее и pnpm. Версия пакетного менеджера указана в `package.json`.

```bash
git clone https://github.com/IzusX/vlad-guide.git
cd vlad-guide
pnpm install --frozen-lockfile
pnpm dev
```

Приложение доступно по адресу [http://localhost:3000](http://localhost:3000).

## Настройка ИИ-провайдера

```bash
cp .env.example .env.local
```

Заполните переменные в `.env.local` и перезапустите сервер:

| Переменная | Назначение |
| --- | --- |
| `AI_API_URL` | Полный URL endpoint для chat completions, включая `/chat/completions` |
| `AI_API_KEY` | Ключ API выбранного провайдера |
| `AI_MODEL` | Идентификатор модели; по умолчанию `gpt-4o-mini` |

Обработчик использует авторизацию `Bearer` и формат `messages` OpenAI Chat Completions. Провайдер и модель должны поддерживать этот формат; значение модели по умолчанию подходит не для каждого сервиса. Подключение, квоты и доступность модели зависят от провайдера.

Переменные читаются только в серверном обработчике. Не используйте для ключа префикс `NEXT_PUBLIC_`: такие переменные доступны клиентскому коду. Файлы `.env*` исключены из Git, кроме `.env.example`, который не содержит ключей.

### Работа чата

```text
Выбор места → вопрос → POST /api/chat
                           ↓
                   Поиск места в каталоге
                           ↓
                Описание места + вопрос
                           ↓
              OpenAI-совместимый провайдер
                           ↓
                    Ответ в интерфейсе
```

Браузер передаёт идентификатор места и вопрос. Сервер получает описание из каталога и добавляет его в контекст модели. Ключ не передаётся в браузер. Инструкция модели ограничивает ответ предоставленным контекстом, но сама по себе не гарантирует достоверность — качество ответа зависит от контента и модели.

Текущая реализация отправляет каждый вопрос отдельно, без истории диалога. Загрузка фотографий, распознавание объектов и бронирование не реализованы.

### HTTP API

`POST /api/chat`

```json
{
  "placeId": "railway-station",
  "question": "Чем интересно это место?"
}
```

Формат успешного ответа:

```json
{
  "answer": "Текст ответа",
  "source": "ai",
  "placeId": "railway-station"
}
```

`source` принимает значение `ai` для ответа провайдера или `fallback` для справочной информации без подключения к ИИ. Для отсутствующих полей используется HTTP 400, для неизвестного места — 404, для ошибки обращения к провайдеру — 502.

## Редактирование каталога

### Места — `data/places.json`

Каждое место содержит:

- `id` — уникальный идентификатор;
- `name` и `address` — название и адрес;
- `short` — краткое описание;
- `description` — подробный рассказ и контекст для чата;
- `lat`, `lng` — координаты;
- `category` — тематические категории.

### Маршруты — `data/routes.json`

Каждый маршрут содержит:

- `id`, `title`, `summary` — идентификатор, название и описание;
- `duration` — `1h`, `2h` или `4h`;
- `placeIds` — идентификаторы мест в порядке посещения;
- `tags` — тематические теги.

Идентификаторы в `placeIds` должны существовать в каталоге мест. После изменения данных для production-развёртывания нужна новая сборка.

Карта соединяет точки в заданном порядке прямыми линиями: это визуализация последовательности посещения, а не пошаговая навигация по улицам. Координаты, доступность проходов, исторические сведения и оценку времени следует проверять при обновлении каталога.

## Проверки и production-запуск

```bash
pnpm lint
pnpm build
pnpm start
```

`build` собирает приложение и проверяет TypeScript. `start` запускает готовую сборку.

## Развёртывание

Приложение можно развернуть на Vercel или сервере с поддержкой Next.js и Node.js. Переменные `AI_API_URL`, `AI_API_KEY` и `AI_MODEL` задаются в настройках окружения хостинга, а не в репозитории. Статический хостинг без серверных обработчиков не подходит для `/api/chat`.

Для карты требуется доступ к тайлам OpenStreetMap; стандартные изображения маркеров загружаются с unpkg. Шрифты Inter и Libre Baskerville загружаются при сборке через `next/font` и затем обслуживаются приложением. Возможность бесплатного размещения и лимиты определяются выбранным хостингом и ИИ-провайдером.
